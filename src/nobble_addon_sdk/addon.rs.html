1//! What an addon is: the trait an author implements, and its vocabulary.
2//!
3//! Moved here from `nobble-core`, where its own module doc already said these
4//! types were "destined to be part of the public SDK (ADR-0010, FR-047)". They
5//! arrived without a single `use crate::` line, so the move was a lift rather
6//! than an extraction — the boundary was already where it needed to be.
7//!
8//! **Nothing here depends on any other Nobble crate, and it must stay that
9//! way.** Every dependency added here is one a third-party addon author
10//! inherits, and FR-044 says an addon must be buildable against only the public
11//! repositories.

19/// Where an addon keeps its own credentials (ADR-0013, FR-046).
20///
21/// # Why there is no `addon` parameter
22///
23/// Because there used to be, and it was a hole. `nobble-core`'s `SecretStore`
24/// reads `fn get(&self, addon: &str, key: &str)`, and every addon was handed
25/// the same live handle to it — so **any addon could read any other addon's
26/// credentials** by passing a different string. `get("spotify",
27/// "refresh_token")` from inside an unrelated addon returned the token.
28///
29/// That could not be fixed by narrowing the trait while addons shared an
30/// address space: a handle to the store *is* the capability, and asking a third
31/// party not to use one they hold is not a control. It is fixed by taking the
32/// namespace out of the caller's hands entirely. An addon says which *key* it
33/// wants and never which addon it is; whoever hands out the handle decides
34/// that, and in the daemon it is bound to the addon the handle was made for.
35///
36/// The result is a type in which the old mistake cannot be written down.
37/// [ADR-0016](../../../docs/decisions/0016-addon-process-boundary.md).
38pub trait Credentials: Send + Sync {
39    /// Read one of this addon's credentials.
40    fn get(&self, key: &str) -> Option<String>;
41
42    /// Store one.
43    ///
44    /// # Errors
45    /// If the platform store refused it.
46    fn set(&self, key: &str, value: &str) -> Result<(), String>;
47
48    /// Forget one. Absent is the outcome, so forgetting nothing is success.
49    fn clear(&self, key: &str);
50}
51
52/// A shared [`Credentials`], because an addon needs it after configuration too.
53pub type CredentialHandle = Arc<dyn Credentials>;

67/// What kind of input an action expects.
68///
69/// [ADR-0012]. Declared rather than inferred, because the two are not
70/// interchangeable and binding one to the other is always a mistake: a fader
71/// bound to "next track" would skip a hundred tracks across one sweep, and a
72/// key bound to "set volume" has no position to send.
73///
74/// [ADR-0012]: ../../../docs/decisions/0012-addon-actions-carry-data.md
75#[derive(Debug, Clone, Copy, PartialEq, Eq)]
76pub enum Trigger {
77    /// A press. The ordinary case, and the default an addon author should
78    /// reach for.
79    Momentary,
80    /// A position — a fader, `0..=16383`.
81    ///
82    /// The daemon coalesces these, so an action sees where the fader ended up
83    /// rather than every point it passed through. An action that needs the
84    /// whole gesture is a different thing and this is not it.
85    Continuous,
86}
87
88impl Trigger {
89    /// How it is spelled on a wire.
90    ///
91    /// # Why this is a method and not a `match` at each end
92    ///
93    /// Because it was three `match`es, and they had to agree without anything
94    /// making them. The addon-to-daemon encoder lived in
95    /// [`run`](crate::run), the daemon-to-interface encoder in
96    /// `nobble_rpc::AddonDto::of`, and the decoder between them was
97    /// `if a.trigger == "continuous"` in the daemon — with a TypeScript
98    /// `=== "continuous"` at the far end comparing against the result. Five
99    /// hand-written copies of two strings, on a round trip where a single
100    /// disagreement makes a fader silently behave like a key: the decoder's
101    /// `else` branch is `Momentary`, so a renamed encoding does not fail, it
102    /// degrades.
103    ///
104    /// Constitution VI is about exactly that, and the remedy it prefers —
105    /// generated bindings — is unavailable inside one language. One definition
106    /// on the type is the next thing: `nobble-core` re-exports this type, so
107    /// every crate downstream is looking at the same `impl` rather than at its
108    /// own copy of the answer.
109    ///
110    /// **Not a display name.** These are protocol tokens, lowercase because
111    /// that is what is on the wire, and a renaming here is a breaking protocol
112    /// change rather than a wording change. An interface wanting *Momentary*
113    /// with a capital M writes that itself.
114    #[must_use]
115    pub const fn as_wire(self) -> &'static str {
116        match self {
117            Self::Momentary => "momentary",
118            Self::Continuous => "continuous",
119        }
120    }
121
122    /// Read one back, or `None` if this build has no name for it.
123    ///
124    /// An `Option` rather than a default, deliberately. The daemon's decode
125    /// used to fall back to [`Self::Momentary`] for anything unrecognised,
126    /// which turns an addon built against a newer SDK into a fader that behaves
127    /// like a key with nothing reported — a Principle IV collapse. Whether to
128    /// refuse or to default is the caller's decision to state out loud; this
129    /// only declines to make it for them.
130    #[must_use]
131    pub fn from_wire(s: &str) -> Option<Self> {
132        match s {
133            "momentary" => Some(Self::Momentary),
134            "continuous" => Some(Self::Continuous),
135            _ => None,
136        }
137    }
138}

140/// What a parameter holds, so an interface can offer the right editor.
141///
142/// A hint, not a storage type — every parameter is stored as a string
143/// (ADR-0012). Widening this is additive; a client that does not recognise a
144/// kind falls back to a text box and stays useful.
145#[derive(Debug, Clone, Copy, PartialEq, Eq)]
146#[non_exhaustive]
147pub enum ParamKind {
148    /// Free text.
149    Text,
150    /// An application identity, in whatever form the foreground watcher
151    /// reports. The interface can offer "the application you were just in"
152    /// rather than asking someone to type an executable name from memory.
153    App,
154}
155
156impl ParamKind {
157    /// How it is spelled on a wire. See [`Trigger::as_wire`] for why this is
158    /// here rather than at each end.
159    ///
160    /// **Exhaustive, and that is the point of putting it in this crate.** This
161    /// type is `#[non_exhaustive]`, so every match on it *outside* the SDK must
162    /// carry a wildcard — which is how `nobble_rpc::param_kind_name` came to
163    /// have a `ParamKind::Text | _ => "text"` arm defending against a variant
164    /// that cannot exist in a build that compiled. Here the wildcard is not
165    /// required, so adding a kind fails to compile at the one site that has to
166    /// decide what it is called.
167    #[must_use]
168    pub const fn as_wire(self) -> &'static str {
169        match self {
170            Self::Text => "text",
171            Self::App => "app",
172        }
173    }
174
175    /// Read one back, or `None` if this build has no name for it.
176    ///
177    /// Unlike [`Trigger::from_wire`], defaulting is the *documented* behaviour
178    /// for a caller here: this type's own note says widening it is additive and
179    /// a client that does not recognise a kind should offer a text box and stay
180    /// useful. The `Option` is still the honest return, because "I do not know
181    /// this one" and "this one is text" are different facts and only the caller
182    /// knows whether the difference matters to it.
183    #[must_use]
184    pub fn from_wire(s: &str) -> Option<Self> {
185        match s {
186            "text" => Some(Self::Text),
187            "app" => Some(Self::App),
188            _ => None,
189        }
190    }
191}

193/// Whether something the platform named is the application a binding meant.
194///
195/// Here rather than in each addon, because [`ParamKind::App`] is declared here
196/// and an addon author has no way to guess how to compare one. The value
197/// stored in a binding is whatever Nobble's foreground watcher reports —
198/// `exe:spotify.exe` — and what the addon is comparing it against comes from
199/// somewhere else entirely, in whatever form *that* API uses.
200///
201/// So the comparison is on the **stem**: `exe:spotify.exe` and `Spotify.exe`
202/// both reduce to `spotify`. The Windows media session reports `Spotify.exe`
203/// for a desktop install and `SpotifyAB.SpotifyMusic_…!Spotify` for the Store
204/// build, and matching either exactly would work on one machine and not the
205/// next.
206///
207/// An empty target matches **nothing**, which is the opposite of what an
208/// unconstrained match would do. Naming a target means "this one", and a
209/// blank field that matched everything would turn a typo into a key that
210/// controls whatever happens to be loudest.
211///
212/// ```
213/// # use nobble_addon_sdk::app_matches;
214/// assert!(app_matches("Spotify.exe", "exe:spotify.exe"));
215/// assert!(app_matches("SpotifyAB.SpotifyMusic_zpdnekdrzrea0!Spotify", "exe:spotify.exe"));
216/// assert!(!app_matches("chrome.exe", "exe:spotify.exe"));
217/// assert!(!app_matches("Spotify.exe", ""));
218/// ```
219#[must_use]
220pub fn app_matches(reported: &str, target: &str) -> bool {
221    let stem = target
222        .rsplit(':')
223        .next()
224        .unwrap_or(target)
225        .trim_end_matches(".exe")
226        .trim_end_matches(".EXE")
227        .to_ascii_lowercase();
228    // `Invocation::param` already treats a cleared field as absent, so reaching
229    // here with an empty target is a bug rather than a user choice.
230    !stem.is_empty() && reported.to_ascii_lowercase().contains(&stem)
231}

233/// What one parameter holds: a value, or several.
234///
235/// [ADR-0022]. A parameter is single-valued unless its declaration says
236/// otherwise, and both shapes live in the same map because a binding stores one
237/// map whatever its parameters declared.
238///
239/// # Why an enum rather than always a list
240///
241/// Because of what it costs on disk. `#[serde(untagged)]` renders these as
242/// `app = "spotify"` and `apps = ["discord", "game"]` in the same TOML table,
243/// so a configuration written before lists existed parses unchanged and needs
244/// no migration rung. Making every value a list would have rewritten every
245/// binding anybody has, to express something almost none of them use.
246///
247/// It is also what `006-FR-024a-i` asks for in the negative: a list "MUST be
248/// widened rather than worked around with a delimiter convention the interface
249/// cannot render". A TOML array is how TOML writes a list. There is no
250/// convention to learn, and nothing to escape.
251///
252/// [ADR-0022]: ../../../docs/decisions/0022-addon-supplied-choices.md
253#[derive(Debug, Clone, PartialEq, Eq, Serialize, Deserialize)]
254#[serde(untagged)]
255pub enum ParamValue {
256    /// One value. What every parameter was before ADR-0022.
257    One(String),
258    /// Several, in the order the user arranged them.
259    Many(Vec<String>),
260}
261
262impl ParamValue {
263    /// The single value, or `None` if this holds a list.
264    ///
265    /// **Not the first element**, deliberately. An addon that declared a
266    /// single-valued parameter and receives a list has been given something it
267    /// did not ask for, and quietly using the first entry would silently ignore
268    /// the rest — the failure being a key that mutes one of the three
269    /// applications somebody named. `None` reaches the required-parameter check
270    /// in `Registry::perform` and fails loudly instead.
271    #[must_use]
272    pub fn one(&self) -> Option<&str> {
273        match self {
274            Self::One(v) if !v.is_empty() => Some(v),
275            Self::One(_) | Self::Many(_) => None,
276        }
277    }
278
279    /// Every value, whether this holds one or several.
280    ///
281    /// A single value reads as a list of one, because an addon that declared
282    /// `multiple` should not have to care how the user happened to fill it in —
283    /// and a file written before lists existed contains exactly that case.
284    /// Empty strings are dropped for the same reason [`Self::one`] rejects
285    /// them: a cleared box is not a configured value.
286    #[must_use]
287    pub fn all(&self) -> Vec<&str> {
288        match self {
289            Self::One(v) => {
290                if v.is_empty() {
291                    Vec::new()
292                } else {
293                    vec![v.as_str()]
294                }
295            }
296            Self::Many(vs) => vs
297                .iter()
298                .map(String::as_str)
299                .filter(|s| !s.is_empty())
300                .collect(),
301        }
302    }
303}
304
305impl From<&str> for ParamValue {
306    fn from(v: &str) -> Self {
307        Self::One(v.to_owned())
308    }
309}

320/// A named list of options an addon offers, which a parameter can draw from.
321///
322/// [ADR-0022]. **Named rather than attached to one parameter**, and the third
323/// reason below is the one that decided it:
324///
325/// - a live fetch is then one addon and one id, where a parameter would need
326///   `(addon, action, param)` — and a *setting*'s parameter has no action;
327/// - two parameters can share one list, so a pin and a priority pointing at the
328///   same people cannot show two different rosters;
329/// - **composition belongs to the addon.** `006-FR-011b` wants the current call,
330///   then people remembered from previous calls, then free text — an ordering
331///   that is Discord's business. With a named source the addon returns one flat
332///   ordered list and the interface renders it, so "remembered people" needs no
333///   interface support at all.
334///
335/// [ADR-0022]: ../../../docs/decisions/0022-addon-supplied-choices.md
336#[derive(Debug, Clone, Copy, PartialEq, Eq)]
337pub struct AddonChoices {
338    /// Stable id, unique within the addon. A parameter names this.
339    pub id: &'static str,
340    /// What the list is, for the editor's heading and its empty state.
341    pub name: &'static str,
342    /// Whether the values must be asked for rather than read from below.
343    ///
344    /// A **declared** source is fixed for the life of the daemon and arrives
345    /// with everything else. A **live** one changes — a voice roster, the
346    /// playlists on an account — and is fetched when somebody opens the picker
347    /// and at no other time. Not polled: a timer would cost idle CPU for a
348    /// picker nobody has open, which `006-FR-027` forbids and `006-SC-008`
349    /// measures.
350    pub live: bool,
351    /// Every value, for a declared source. Empty when [`Self::live`].
352    pub values: &'static [AddonChoice],
353}

355/// One thing an action needs to know, declared so an interface can ask for it.
356///
357/// The point of declaring rather than parsing a free-text argument: FR-048
358/// wants addon configuration built from the shared component library, and there
359/// has to be something to build it *from*. A third-party addon gets the same
360/// editor as a first-party one with no code in the interface.
361#[derive(Debug, Clone, Copy, PartialEq, Eq)]
362pub struct AddonParam {
363    /// Stable identifier, and the key a binding stores it under. Renaming one
364    /// silently drops whatever the user had chosen.
365    pub id: &'static str,
366    /// What to call it.
367    pub name: &'static str,
368    /// What it is for, in a sentence.
369    pub description: &'static str,
370    /// What it holds.
371    pub kind: ParamKind,
372    /// Whether the action can run without it.
373    ///
374    /// An optional parameter is a real thing rather than an oversight: the
375    /// media addon's target application is absent for "whatever is playing",
376    /// which is the behaviour most people want most of the time.
377    pub required: bool,
378    /// Whether it holds several values rather than one (`006-FR-024a-i`).
379    ///
380    /// Orthogonal to [`Self::kind`] on purpose. What a value *means* and how
381    /// many of them there are are different questions, and folding one into the
382    /// other is what produces `AppList`, `ParticipantList`, `PlaylistList` —
383    /// one new kind every time somebody wants a list of something.
384    pub multiple: bool,
385    /// The id of an [`AddonChoices`] this draws its options from, if any.
386    ///
387    /// `None` is free text, which is what every parameter was before ADR-0022
388    /// and what a choice-backed one degrades to when its list is unavailable.
389    pub choices: Option<&'static str>,
390}
391
392impl AddonParam {
393    /// A parameter with nothing set, to build from.
394    ///
395    /// Exists so the next field added here does not break every `const` array
396    /// an addon writes: `AddonParam { id: "app", ..AddonParam::BASE }` compiles
397    /// in a `const`, and adding a field to `BASE` costs its authors nothing.
398    /// **It does not save the arrays that already name every field**, which is
399    /// why the ones in this repository were converted when this was added.
400    pub const BASE: Self = Self {
401        id: "",
402        name: "",
403        description: "",
404        kind: ParamKind::Text,
405        required: false,
406        multiple: false,
407        choices: None,
408    };
409}

435/// One keystroke, exactly as the device will send it.
436///
437/// # Why this crate spells the HID vocabulary again
438///
439/// It has no choice. Nothing here may depend on another Nobble crate — the rule
440/// at the top of this module, and FR-044 behind it — so `nobble_core::HidAction`
441/// is unreachable from an addon author's build, and Constitution VI's preferred
442/// answer, generated bindings, does not cross a repository boundary that exists
443/// on purpose (FR-043, FR-049). The alternative to restating the shape is not
444/// restating it somewhere better; it is being unable to declare a keystroke at
445/// all, and then FR-024 has no answer.
446///
447/// What *is* a choice is how much gets restated and how the copy is held in
448/// step. These variants, their field names and their serde spelling in
449/// [`KeystrokeDecl`](crate::protocol::KeystrokeDecl) match
450/// `nobble_rpc::ActionDto::HidTap` and `HidConsumer` one for one, so the object
451/// crossing this pipe is the same JSON text a binding is saved as, and the
452/// daemon's conversion is a rename-free `match` a reader can check by eye. A
453/// test in `nobble-service` — the only crate that can see both — pins that, and
454/// stands in for the generated binding.
455///
456/// **That is weaker than one definition and is recorded as such rather than
457/// argued away.** Nothing makes a new `HidAction` variant a compile error here,
458/// because Cargo cannot see across the boundary. Two things bound the damage:
459/// the drift is asymmetric — a variant added there narrows what this can say, a
460/// variant added here breaks the daemon's exhaustive bridge — and what is copied
461/// is USB HID's vocabulary rather than Nobble's, so it is not a format anyone
462/// here is free to change.
463///
464/// # Why exactly these two, and why not MIDI
465///
466/// The cut is made by an existing function rather than by judgement.
467/// `ActionDto::from_binding` has arms for `HidTap` and `HidConsumer`, and its
468/// `_ => return None` covers key sequences and mouse movement, which have no
469/// on-disk form — so an addon declaring one would declare a binding
470/// `check_supported` refuses to save, and it fails the **whole file** rather
471/// than the one key.
472///
473/// The narrower reading matters as much. One chord cannot type a string, and a
474/// sequence is precisely the mechanism the contract rules out when it says an
475/// addon able to ask the device to send anything at any time *"would be a
476/// keylogger with extra steps"*. Excluding it in the type leaves no check for
477/// anyone to forget.
478///
479/// MIDI is left out on different grounds, and the omission is **not** a claim
480/// that device-resolved means keyboard. `Binding::Midi` is device-resolved too
481/// and a control change is inherently continuous, so resolution and trigger are
482/// genuinely independent axes. But `midi_note` and `midi_cc` are already
483/// first-class binding kinds with their own editors, so there is no
484/// discoverability gap for an addon to close. Adding a variant later is
485/// additive; adding one now is speculative.
486///
487/// Deliberately **not** `#[non_exhaustive]` — the opposite choice from
488/// [`ParamKind`], for the reason that separates them: an unfamiliar parameter
489/// kind has a useful fallback, a text box, and an unfamiliar keystroke has none.
490/// A wildcard arm here is how a device silently sends nothing. Adding a variant
491/// *should* fail to compile in the daemon that has to translate it, which is
492/// what [`Request`](crate::protocol::Request) says for itself.
493#[derive(Debug, Clone, Copy, PartialEq, Eq)]
494pub enum DeviceKeystroke {
495    /// Press and release one key, with modifiers held.
496    ///
497    /// **What is declared here is a suggestion the user is expected to change**,
498    /// and an addon that treats it as a contract has misunderstood the field.
499    /// Discord ships no keybind for Toggle Mute — the user invents one — so
500    /// whatever is declared has to be transcribed into Discord by hand anyway.
501    /// [`Self::Consumer`] is the opposite case: there the addon knows the answer.
502    Tap {
503        /// A HID usage code, **not** a character — the same distinction
504        /// `HidKey` makes on the daemon side, for the same reason: a keystroke
505        /// authored on a QWERTZ layout and pressed on a QWERTY host produces a
506        /// different character, and hiding that makes it invisible until
507        /// somebody complains. Usage `0x10` is the key labelled **M** on ANSI
508        /// and the key labelled **,** on AZERTY, so an addon's choice of chord
509        /// can collide with something on a layout its author never saw. That is
510        /// what the editor is for.
511        key: u8,
512        /// Held with it.
513        ctrl: bool,
514        /// Held with it.
515        shift: bool,
516        /// Held with it.
517        alt: bool,
518        /// Held with it — Windows, Command, Super.
519        gui: bool,
520    },
521    /// A Consumer Control usage — the media keys.
522    ///
523    /// Here because [ADR-0021] intends `media` to gain a device-resolved
524    /// play/pause as a *new* action, and calls its case stronger than Discord's:
525    /// a consumer usage is layout-free and needs nothing arranged elsewhere, so
526    /// the addon genuinely knows the number and the declaration is a fact rather
527    /// than a suggestion. A type that could not say so would have made the
528    /// adoption impossible.
529    ///
530    /// [ADR-0021]: ../../../docs/decisions/0021-addon-device-resolved-actions.md
531    Consumer {
532        /// The usage.
533        usage: u16,
534    },
535}

537/// One thing an addon *names* and the **device** does, with no addon running.
538///
539/// [ADR-0021]. Discord's Toggle Mute is the case this exists for: it is a
540/// *global* keybind, so a device that sends it controls Discord from the
541/// background — at the login screen, inside a full-screen game, and with Nobble
542/// closed. That is Principle V and [ADR-0007], and a stronger promise than any
543/// addon can otherwise make.
544///
545/// Binding one writes a HID binding. [`Addon::perform`] is never called, the
546/// addon need not be running, and it need not ever have been *allowed* to run —
547/// ADR-0021 exempts these from the permission grant, because the grant's only
548/// lever is *do not start the process* and a keystroke in flash starts none.
549/// That is defensible only because what the device will send is disclosed when
550/// the key is bound and frozen there.
551///
552/// # Why this is not [`AddonAction`] with more fields
553///
554/// Because the two are not the same shape, and one struct would carry fields
555/// that are load-bearing in one regime and meaningless in the other, with
556/// nothing but a doc comment saying which.
557///
558/// A device-resolved action has no [`Trigger`]: a keystroke has no position to
559/// send, so continuous is incoherent *by construction* rather than merely
560/// disallowed. It has no [`AddonParam`]s: a resolved binding carries no
561/// parameters at all, so a runtime-varying one is impossible here rather than
562/// late. ADR-0021 calls both impossible, and this is the shape in which they
563/// cannot be *written down* — which is the discipline `Binding` already states
564/// for itself, that the kind and the payload cannot be constructed disagreeing.
565///
566/// The honest limit of that: an addon written in something other than Rust can
567/// still put `"trigger"` and `"params"` in the JSON, because serde ignores
568/// fields it was not asked about. What it cannot do is make them *mean*
569/// anything — there is nowhere for the daemon to read them from, so there is no
570/// check to forget. That is a weaker claim than "unrepresentable" and it is the
571/// true one.
572///
573/// The cost of a second list is real and is paid in one place: **ids share one
574/// namespace with [`Addon::actions`]**, because a binding stores one string and
575/// cannot say which list it came from. A collision has no type to prevent it,
576/// and the daemon must refuse it by name rather than guess — otherwise binding
577/// the device-resolved twin resolves to the host-resolved one, which is the
578/// *"silently fall back to a host-resolved call when the daemon happens to be
579/// running"* the contract forbids outright. Worth knowing that ids within
580/// [`Addon::actions`] are not checked for uniqueness today either, and
581/// `Registry::perform` takes the first match; this makes an existing unenforced
582/// invariant load-bearing rather than inventing a new hazard.
583///
584/// # A separate list here is not a separate group in the interface
585///
586/// ADR-0021 requires these to appear in the addon's action list *alongside* the
587/// host-resolved ones, reported per row rather than segregated, because grouping
588/// by mechanism is what FR-024b forbids in the very addon that will hold both
589/// families. Nothing here decides that: the daemon assembles one list for the
590/// interface out of both, the way it already computes `applies` per row rather
591/// than reading it from a declaration. What an author writes and what a user
592/// reads have never been the same shape.
593///
594/// [ADR-0021]: ../../../docs/decisions/0021-addon-device-resolved-actions.md
595/// [ADR-0007]: ../../../docs/decisions/0007-input-delivery.md
596#[derive(Debug, Clone, Copy, PartialEq, Eq)]
597pub struct DeviceAction {
598    /// Stable identifier, and what the binding records as provenance so that
599    /// removing the addon reports the binding broken rather than leaving a bare
600    /// keystroke nobody can explain (`003-FR-066` with `003-FR-047`). It must
601    /// not change once anyone could have bound it, and it must not collide with
602    /// an [`AddonAction::id`] on the same addon.
603    pub id: &'static str,
604    /// What to call it in a menu. The whole reason not to leave this as a
605    /// hand-configured HID binding: the daemon's own summary of a raw tap is
606    /// `Ctrl+Shift+usage 0x10`, which is accurate and unexplainable.
607    pub name: &'static str,
608    /// What it does, in a sentence.
609    pub description: &'static str,
610    /// What the device sends **by default**. The user can change it, and must be
611    /// able to, because it has to match whatever they set in the other
612    /// application and only they know what that is.
613    ///
614    /// Read once, when the key is bound, and never re-resolved on load
615    /// (ADR-0021). So a later version of the addon cannot change what an
616    /// already-bound key types — and a wrong default is wrong for everyone who
617    /// already bound it, with no upgrade path short of rebinding. That is the
618    /// right way round: the alternative is an addon update silently altering a
619    /// key the user authored.
620    pub keystroke: DeviceKeystroke,
621    /// The step outside Nobble that has to happen for this to work, if there is
622    /// one: *"Set this keybind in Discord: User Settings > Keybinds."*
623    ///
624    /// Free text, shown at the moment of binding, and **never parsed** — which
625    /// is what lets it also carry a suggested chord in prose without that
626    /// suggestion becoming a grammar with a compatibility surface of its own.
627    /// The day something reads a keystroke out of this string, this field has
628    /// quietly become the interface [`DeviceKeystroke`] exists to be instead.
629    ///
630    /// `None` where there is nothing to arrange elsewhere, which is the case a
631    /// future device-resolved play/pause is in. An [`Option`] rather than an
632    /// empty string, because the two states oblige the interface differently:
633    /// `Some` means it must not claim the key works until the user confirms the
634    /// step (FR-024), since Nobble cannot read another application's settings
635    /// and must say so rather than pretend. A sentinel would make *the author
636    /// left it blank* and *there is nothing to do* the same value.
637    pub prerequisite: Option<&'static str>,
638}

640/// What an action was given when it ran.
641///
642/// Two sources, and keeping them apart is the whole design. **Parameters** were
643/// chosen when the binding was authored and are saved with it; the **value**
644/// was produced by the input a moment ago and is saved nowhere. Merging them
645/// into one map would let a fader position be persisted, which is the sort of
646/// thing that works until someone restarts the daemon and their volume jumps.
647#[derive(Debug, Clone, Copy)]
648pub struct Invocation<'a> {
649    params: &'a BTreeMap<String, ParamValue>,
650    value: Option<u16>,
651}
652
653/// Nothing configured, for an action that takes no parameters.
654static NO_PARAMS: std::sync::LazyLock<BTreeMap<String, ParamValue>> =
655    std::sync::LazyLock::new(BTreeMap::new);
656
657impl<'a> Invocation<'a> {
658    /// A press, with the binding's parameters.
659    #[must_use]
660    pub fn press(params: &'a BTreeMap<String, ParamValue>) -> Self {
661        Self {
662            params,
663            value: None,
664        }
665    }
666
667    /// A position, with the binding's parameters.
668    #[must_use]
669    pub fn moved(params: &'a BTreeMap<String, ParamValue>, value: u16) -> Self {
670        Self {
671            params,
672            value: Some(value),
673        }
674    }
675
676    /// A press with nothing configured. For tests, and for actions that take
677    /// no parameters.
678    #[must_use]
679    pub fn bare() -> Self {
680        Self {
681            params: &NO_PARAMS,
682            value: None,
683        }
684    }
685
686    /// One parameter, if the binding set it.
687    ///
688    /// Absent and empty are the same answer here. A text box someone cleared
689    /// stores `""`, and an addon checking only for absence would then treat a
690    /// deliberately blank field as a configured one.
691    /// **A parameter holding a list reads as absent here**, rather than as its
692    /// first entry. See [`ParamValue::one`]: an addon that declared one value
693    /// and silently used the first of several would mute one of the three
694    /// applications somebody named and report nothing.
695    #[must_use]
696    pub fn param(&self, id: &str) -> Option<&str> {
697        self.params.get(id).and_then(ParamValue::one)
698    }
699
700    /// Every value of one parameter, whether it holds one or several.
701    ///
702    /// The accessor a `multiple` parameter reads. A single value reads as a
703    /// list of one, so an addon does not have to care how the user happened to
704    /// fill it in — and a configuration written before lists existed contains
705    /// exactly that case.
706    #[must_use]
707    pub fn param_all(&self, id: &str) -> Vec<&str> {
708        self.params.get(id).map(ParamValue::all).unwrap_or_default()
709    }
710
711    /// The map as it was stored, for a host that has to forward it verbatim.
712    ///
713    /// Not for addons: an addon wants [`Self::param`] or
714    /// [`Self::param_all`]. This exists because the daemon builds an
715    /// invocation on one side of a pipe and has to put the same thing back on
716    /// the wire on the other, and re-deriving it from the accessors would turn
717    /// a list into whatever the accessors happened to flatten it to.
718    #[must_use]
719    pub fn raw_params(&self) -> &BTreeMap<String, ParamValue> {
720        self.params
721    }
722
723    /// Every parameter, for reporting.
724    ///
725    /// A list renders comma-separated, because this feeds a log line rather
726    /// than anything that parses it back.
727    pub fn params(&self) -> impl Iterator<Item = (&str, String)> {
728        self.params
729            .iter()
730            .map(|(k, v)| (k.as_str(), v.all().join(", ")))
731    }
732
733    /// The raw position, `0..=16383`, for a continuous action.
734    #[must_use]
735    pub fn value(&self) -> Option<u16> {
736        self.value
737    }
738
739    /// The position as a fraction of full travel, `0.0..=1.0`.
740    ///
741    /// Provided so the common case is one call rather than a division everyone
742    /// writes slightly differently. **Not** a taper: audio wants a curve, and
743    /// only the addon knows whether its target is already logarithmic.
744    #[must_use]
745    pub fn fraction(&self) -> Option<f32> {
746        self.value.map(|v| f32::from(v) / f32::from(FADER_MAX))
747    }
748}

750/// One thing an addon needs configuring once, rather than per key.
751///
752/// [ADR-0013]. A client id, an endpoint, a token. Declared with the same
753/// vocabulary as an action's parameters so the interface renders a settings
754/// page with no code per addon, which is the same FR-048 reasoning.
755///
756/// [ADR-0013]: ../../../docs/decisions/0013-addon-settings-and-secrets.md
757#[derive(Debug, Clone, Copy, PartialEq, Eq)]
758pub struct AddonSetting {
759    /// What to ask for.
760    pub param: AddonParam,
761    /// Whether this is a credential.
762    ///
763    /// A secret is kept in the OS credential store rather than in a file, and
764    /// **is never sent back** — the interface can set one and can ask whether
765    /// one exists, and cannot read it. FR-026 makes profiles shareable, and a
766    /// refresh token that could be read back is one that ends up in a paste.
767    pub secret: bool,
768}

770/// Something an addon needs to be allowed to do (FR-046).
771///
772/// Declared as a set the addon needs *in order to work*, not as a wish list:
773/// the user grants or refuses the whole declaration, because a half-granted
774/// addon is a matrix of broken states nobody asked for and every one of them
775/// would have to be designed.
776///
777/// # Only one of these is enforced, and this type does not pretend otherwise
778///
779/// [`Self::Credentials`] is real: the daemon holds the credential store and an
780/// addon can only ask, so a refusal is a refusal. The other three are
781/// **declarations shown to the user**, and an ungranted addon is simply not
782/// started — which is a genuine control, because a process that is not running
783/// opens no sockets. What is *not* true is that a *running* addon is confined
784/// to what it declared. Nothing stops a granted addon reaching a host it never
785/// mentioned.
786///
787/// That gap is [ADR-0016]'s, deliberately, and it is named in the interface
788/// rather than papered over: "may reach api.spotify.com" must not be read as
789/// "and nothing else" until platform confinement makes it true.
790///
791/// [ADR-0016]: ../../../docs/decisions/0016-addon-process-boundary.md
792#[derive(Debug, Clone, Copy, PartialEq, Eq)]
793#[non_exhaustive]
794pub enum Permission {
795    /// Reach a host over the network.
796    ///
797    /// One host per declaration rather than a list, so the interface can show
798    /// them as separate lines and so a diff between two versions of an addon
799    /// reads as "it now also wants X".
800    Network {
801        /// The host, as it appears in a URL: `api.spotify.com`.
802        host: &'static str,
803        /// Why, in a few words, shown next to it. An addon that cannot explain
804        /// what it wants a host for is asking the user to guess.
805        reason: &'static str,
806    },
807    /// Read or write files under a path.
808    Files {
809        /// The directory or file, as a path the user would recognise.
810        path: &'static str,
811        /// Whether it writes, or only reads. The distinction is the whole
812        /// difference between "reads your project list" and "can delete it".
813        write: bool,
814        /// Why.
815        reason: &'static str,
816    },
817    /// Start another program.
818    Launch {
819        /// What it starts. `the default browser` is a legitimate answer here —
820        /// this is shown to a person, not matched against anything.
821        program: &'static str,
822        /// Why.
823        reason: &'static str,
824    },
825    /// Keep credentials of its own, in the OS credential store.
826    ///
827    /// The enforced one. Ungranted, the daemon answers every credential ask
828    /// with a refusal, which an addon must survive: it is the same answer as
829    /// "nothing stored yet", and an addon that handles being signed out
830    /// already handles this.
831    Credentials {
832        /// Why. "To stay signed in to your Spotify account" — the account is
833        /// the thing the user is actually deciding about.
834        reason: &'static str,
835    },
836}
837
838impl Permission {
839    /// Why the addon says it needs this.
840    #[must_use]
841    pub const fn reason(&self) -> &'static str {
842        match self {
843            Self::Network { reason, .. }
844            | Self::Files { reason, .. }
845            | Self::Launch { reason, .. }
846            | Self::Credentials { reason } => reason,
847        }
848    }
849}

851/// A named boolean fact an addon publishes about its target.
852///
853/// FR-062. Recording, streaming, in a call, muted, playing. An overlay can be
854/// conditioned on one (ADR-0011), which makes a signal a **resolution input**
855/// and therefore a stronger obligation than FR-047's display state: a stale
856/// label is a cosmetic problem, a stale signal is a device doing the wrong
857/// thing.
858///
859/// Boolean, and FR-063 keeps it that way until a specified need exists for
860/// more. The same reasoning as the RPC being deliberately small: a value set
861/// that grows on speculation grows a conversion for every consumer, and the
862/// consumers here include third-party addons.
863#[derive(Debug, Clone, Copy, PartialEq, Eq)]
864pub struct AddonSignal {
865    /// Stable identifier, **unqualified** — `recording`, not `obs.recording`.
866    /// The addon's own id qualifies it, so an addon cannot claim a name in
867    /// another's space by choosing a clever string.
868    ///
869    /// Stored in configurations, so a rename silently breaks someone's
870    /// overlay, exactly as [`AddonAction::id`] does.
871    pub id: &'static str,
872    /// What to call it.
873    pub name: &'static str,
874    /// What it means, in a sentence. Shown next to a live value, so it has to
875    /// say what *true* means rather than what the signal is about: "Spotify is
876    /// playing" beats "playback state".
877    pub description: &'static str,
878}

880/// What an addon's signals read at one moment.
881///
882/// # Why the daemon asks rather than the addon telling
883///
884/// **Polled, not pushed**, and the reasons are all about what happens when
885/// this interface crosses a process boundary — which FR-045 says it will.
886///
887/// A request/response call survives that move unchanged. A callback does not:
888/// it needs a reverse channel, and a reverse channel is precisely where a
889/// wedged addon becomes a wedged daemon, because something has to be waiting
890/// on it.
891///
892/// Polling also puts the rate limit on the side that suffers from getting it
893/// wrong. A pushing addon that reports a flapping signal thousands of times a
894/// second is a churn source the daemon can only damp *after* paying for it,
895/// and ADR-0011 is explicit that signal churn is flash wear rather than a slow
896/// link. A polled addon cannot produce that by construction.
897///
898/// What polling costs is answered by the addon, not by the poll rate: an
899/// implementation is free to keep a cache fed by platform events and answer
900/// from it, which is what FR-065's "no measurable idle CPU" actually turns on.
901#[derive(Debug, Clone, PartialEq, Eq)]
902pub enum Reading {
903    /// It looked, and these are the values.
904    ///
905    /// Ids must be ones [`Addon::signals`] declares. Anything else is dropped
906    /// by the daemon rather than becoming a signal nobody can find the
907    /// definition of.
908    Values(Vec<(&'static str, bool)>),
909    /// It could not look, and this is why.
910    ///
911    /// FR-064: every signal it publishes then reads false, **and the reason is
912    /// this sentence** rather than "the condition was false". The two states
913    /// are indistinguishable to a user and have different fixes — one is a
914    /// configuration mistake, the other is a closed application.
915    Unavailable(String),
916}
917
918impl Reading {
919    /// A reading of nothing, from an addon that publishes no signals.
920    #[must_use]
921    pub fn none() -> Self {
922        Self::Values(Vec::new())
923    }
924
925    /// The value of one signal, if this reading carries it.
926    #[must_use]
927    pub fn get(&self, signal: &str) -> Option<bool> {
928        match self {
929            Self::Values(values) => values.iter().find(|(id, _)| *id == signal).map(|(_, v)| *v),
930            Self::Unavailable(_) => None,
931        }
932    }
933}

935/// Whether an addon can act at the moment.
936#[derive(Debug, Clone, PartialEq, Eq)]
937pub enum Availability {
938    /// It can.
939    Ready,
940    /// It cannot, and this is why, in words a user can act on.
941    ///
942    /// "Spotify is not running" is useful. "Error 0x80070002" is not: a person
943    /// reading it on a settings page cannot do anything with it.
944    Unavailable(String),
945}

947/// Why performing an action failed.
948#[derive(Debug, Clone, PartialEq, Eq)]
949pub enum AddonError {
950    /// No action by that name. Usually a binding saved against an older
951    /// version of the addon.
952    NoSuchAction(String),
953    /// The addon could not act right now.
954    Unavailable(String),
955    /// It tried and something went wrong.
956    Failed(String),
957}
958
959impl fmt::Display for AddonError {
960    fn fmt(&self, f: &mut fmt::Formatter<'_>) -> fmt::Result {
961        match self {
962            Self::NoSuchAction(a) => write!(f, "no action called {a:?}"),
963            // Both render as their reason. The variants stay separate because
964            // callers distinguish them -- unavailable is worth retrying, failed
965            // is not -- but a reader wants the sentence, not the category.
966            Self::Unavailable(why) | Self::Failed(why) => write!(f, "{why}"),
967        }
968    }
969}

973/// Something that can act on another application's behalf.
974///
975/// Implementations are expected to be cheap to construct and to discover their
976/// target lazily: the daemon builds every addon at startup whether or not the
977/// application it integrates is installed, and a constructor that blocked on a
978/// network call would delay login for all of them.
979pub trait Addon: Send {
980    /// Stable identifier, stored in bindings. Never rename one.
981    fn id(&self) -> &'static str;
982
983    /// What to call it.
984    fn name(&self) -> &'static str;
985
986    /// What it integrates, in a sentence.
987    fn description(&self) -> &'static str;
988
989    /// Everything it can be asked to do.
990    fn actions(&self) -> &'static [AddonAction];
991
992    /// Everything it *names* that the device does on its own (ADR-0021).
993    ///
994    /// Defaulted to nothing, like [`Self::signals`] and [`Self::settings`], and
995    /// for a stronger reason than either: almost every addon has none, and the
996    /// whole point of the declaration is that it is exceptional. An addon
997    /// listing one is saying *this is better as a keystroke than as a call to
998    /// me, and here is what to call it*.
999    ///
1000    /// **[`Self::perform`] is never called for one of these** by a daemon that
1001    /// understands the declaration — it resolved the action to a keystroke when
1002    /// the key was bound, and the press never reaches the host at all. An author
1003    /// implements nothing for them and must not try. A daemon built against an
1004    /// older SDK dropped this field on the way in and will call `perform`
1005    /// anyway; [`run`](crate::run) answers that itself with a failure naming the
1006    /// cause, so an author still implements nothing.
1007    ///
1008    /// Ids share one namespace with [`Self::actions`], because a binding stores
1009    /// one string and cannot say which list it came from.
1010    fn device_actions(&self) -> &'static [DeviceAction] {
1011        &[]
1012    }
1013
1014    /// Whether it could act right now.
1015    ///
1016    /// Asked whenever the interface draws the addon, so it must be quick and
1017    /// must not block. It is allowed to be wrong a moment later — the target
1018    /// application can close between this answer and the next keypress, which
1019    /// is why [`Self::perform`] returns a result of its own rather than
1020    /// trusting this.
1021    fn availability(&self) -> Availability;
1022
1023    /// Do it.
1024    ///
1025    /// `invocation` carries the binding's parameters and, for a
1026    /// [`Trigger::Continuous`] action, the position the input reported.
1027    ///
1028    /// # Errors
1029    /// If the action is unknown, a required parameter is missing, the target is
1030    /// unavailable, or it failed.
1031    fn perform(&mut self, action: &str, invocation: &Invocation<'_>) -> Result<(), AddonError>;
1032
1033    /// Whether an action is worth offering at the moment.
1034    ///
1035    /// For the pair that undo each other — sign in and sign out — where
1036    /// offering both at once means one of them is always the wrong half of a
1037    /// question nobody asked.
1038    ///
1039    /// # This is relevance, not permission
1040    ///
1041    /// [`Self::perform`] deliberately does **not** consult it, and neither
1042    /// does [`Self::actions`], which stays complete. Three consequences, all
1043    /// intended:
1044    ///
1045    /// - A key bound to a hidden action still works. Bindings are authored
1046    ///   once and pressed later, and a key that stopped existing because of
1047    ///   something that happened after it was bound is the failure US9 calls
1048    ///   out.
1049    /// - The action can still be *bound*, because the editor is about what a
1050    ///   key could ever do rather than what is useful this second.
1051    /// - An addon must still handle being asked. Signing out twice succeeds;
1052    ///   this only stops the interface suggesting it.
1053    ///
1054    /// Defaulted to `true`, which is the ordinary case: an action that is
1055    /// worth having is worth having now.
1056    fn applies(&self, _action: &str) -> bool {
1057        true
1058    }
1059
1060    /// One line about what it is currently connected to, when that is a
1061    /// question a user can have.
1062    ///
1063    /// Shown wherever the addon is drawn, next to its name.
1064    ///
1065    /// # Why this is not part of [`Availability`]
1066    ///
1067    /// They answer different questions, and only one of them has an answer
1068    /// when things are fine. `Availability` is *can it act*, and the useful
1069    /// case is the negative one — an addon that cannot act owes the user a
1070    /// reason. `Ready` carries no words because "it works" needs none.
1071    ///
1072    /// This is *what is it working as*, and it is only interesting when the
1073    /// answer is **ready**. "Signed in as Philipp" tells someone which of two
1074    /// Spotify accounts their Save key is filling up, which is invisible from
1075    /// anywhere else in the interface and is exactly the thing they need before
1076    /// pressing Sign out. Folding it into `Ready(String)` would have made every
1077    /// addon that has nothing to say construct an empty one.
1078    ///
1079    /// Defaulted to `None`, which is the ordinary case: an addon that talks to
1080    /// a local application is connected to the only thing it could be.
1081    ///
1082    /// Called whenever the interface draws the addon, so it must be quick and
1083    /// must not block — the same contract as [`Self::availability`], and the
1084    /// same reason. Read it from what the addon already holds; do not go and
1085    /// ask the network.
1086    fn status(&self) -> Option<String> {
1087        None
1088    }
1089
1090    /// Every signal it publishes. FR-062.
1091    ///
1092    /// Defaulted, because most addons only act. An addon that publishes none
1093    /// is not a lesser addon — it is the ordinary case, and the interface
1094    /// should not make it write an empty slice to say so.
1095    fn signals(&self) -> &'static [AddonSignal] {
1096        &[]
1097    }
1098
1099    /// Everything it needs configuring once (ADR-0013).
1100    ///
1101    /// Defaulted for the same reason as signals: most addons need nothing, and
1102    /// the ones that do are the exception.
1103    fn settings(&self) -> &'static [AddonSetting] {
1104        &[]
1105    }
1106
1107    /// Named lists its parameters can draw options from (ADR-0022).
1108    ///
1109    /// Defaulted to nothing, because most parameters are free text and always
1110    /// were. Declared here rather than on the parameter so that two parameters
1111    /// can share one list — a pin and a priority pointing at the same people
1112    /// must not be able to show two different rosters.
1113    ///
1114    /// A source marked [`AddonChoices::live`] carries no values here; the
1115    /// daemon asks for them when somebody opens the picker.
1116    fn choices(&self) -> &'static [AddonChoices] {
1117        &[]
1118    }
1119
1120    /// Everything it needs to be *allowed* to do (FR-046).
1121    ///
1122    /// Defaulted to nothing, and that default is the honest one for more
1123    /// addons than it looks: an addon that drives a local API — the media
1124    /// session, the audio mixer — reaches no host, opens no file and keeps no
1125    /// account, so it has nothing to ask for and the user is never asked.
1126    ///
1127    /// **An addon declaring anything here does not run until the user grants
1128    /// it.** So the list is what the addon needs, not what it might one day
1129    /// like: every entry is a question somebody has to answer before the addon
1130    /// works at all, and an addon that asks for more than it uses is training
1131    /// people to grant without reading.
1132    fn permissions(&self) -> &'static [Permission] {
1133        &[]
1134    }
1135
1136    /// Take its settings, and a place to keep its own credentials.
1137    ///
1138    /// Called at startup and whenever the settings change, so an addon holds
1139    /// what it needs rather than asking. [`Credentials`] arrives as a handle
1140    /// rather than a value because an addon needs it *later* too — a refreshed
1141    /// token has to go back, and that happens mid-action rather than at
1142    /// configuration time.
1143    fn configure(&mut self, _values: &BTreeMap<String, String>, _credentials: CredentialHandle) {}
1144
1145    /// Read every signal it publishes, now.
1146    ///
1147    /// Called on the signal poll, **never on the input path** — the same rule
1148    /// as [`Self::perform`], and for a stronger reason: this runs on a timer,
1149    /// so an implementation that blocked for a second would do it forever
1150    /// rather than once per keypress.
1151    ///
1152    /// See [`Reading`] for why this is a question the daemon asks rather than
1153    /// something the addon announces.
1154    fn read_signals(&mut self) -> Reading {
1155        Reading::none()
1156    }
1157}
